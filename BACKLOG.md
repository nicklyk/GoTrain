1. **B-52 · GoTrain · A duration picked as 0:00 is saved as 5:00 by the editors, but as 0 by "Adjust for today"**
   Why: the exercise-duration picker offers 0:00, and the three places that take it disagree about what it means. The library editor (`saveGex` ~2986) and the plan exercise editor (`savePlanEx` ~3096) store `durFieldValue(...)||300`, so a 0 becomes 5:00 silently; "Adjust for today" (`saveAdjust` ~2004) stores the 0 as the day's override (read in code; not run tonight). Reproduced tonight (v43, headless Chromium): open *New exercise*, set it timed, pick 0:00 and confirm — the field reads "0:00" — then save: the stored `durationSecs` is 300, and reopening the editor shows 5:00. The user picked one value, saw it, and got another. Make the rule the same everywhere: an exercise duration cannot be 0, so the picker opened for an exercise duration (the three `durFieldOpen(...,false,0)` calls for `gex-dur`, `mce-dur` and `adj-durationSecs`, not the pause pickers, where 0 means no rest) does not confirm 0:00 — it snaps to the smallest step, 0:05, which the field then shows; and the two editors keep a value they were given (`??`-style null check rather than `||`), keeping 300 only when the field has no value at all.
   Verify: browser test: picking 0:00 for a new library exercise, a plan exercise and in "Adjust for today" leaves each field showing 0:05 and stores 5; picking 1:30 still stores 90; a new exercise left untouched still stores 300; a pause picker still accepts 0:00 and stores 0.

4. **B-58 · GoTrain · Importing while storage is full drops the import after the alert**
   Why: follow-up from PR #23 (B-51, v44), added at the owner's request. Since v44 a save that hits the storage quota alerts once and lets the app carry on from memory. `importData` (~3345-3346) still calls `saveState(); location.reload();` regardless of the result, so an import made while storage is full shows the "storage is full" alert and then reloads to the old stored state: the imported file is dropped, and the History and plans it held are not on screen to export. When the save succeeds, keep today's reload.

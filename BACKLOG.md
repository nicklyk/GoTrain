1. **B-45 · omarchy-gotrain · `export -o` into a folder, or a folder that does not exist, ends in a traceback**
   Why: `cmd_export` (~1766) hands `-o` straight to `Path.write_text`, for both the JSON and `--csv`. Reproduced tonight (1.4.4, `tests/fixtures/baseline.json` archive): `export -o ~/Downloads` — the natural thing to type when the file is meant for the phone — prints an `IsADirectoryError` traceback and exits 1; `-o missing/dir/out.json` prints `FileNotFoundError`. A traceback from the command that makes the user's backup reads like archive damage. The same write also truncates an existing file before writing it, so a write that fails part-way (disk full) destroys the previous backup at that path. Refuse a directory and a missing parent with a one-line `die()` that names the path, and write to a temporary file beside the target, then `os.replace` it, so the old file survives any failure. Do not invent a file name inside the folder: a `gotrain-*.json` written into the watch folder would itself be picked up by `sync`.
   Verify: new test: `export -o <dir>` and `export --csv -o <dir>` exit non-zero with the path in the message and no `Traceback`; a missing parent likewise; `-o file.json` still writes the same JSON as before and prints its count; with an existing file at the target and the write made to fail (a monkeypatched `json.dumps` or a read-only directory), the old file's contents are unchanged and no temporary file is left behind.
   Size: small

2. **B-56 · omarchy-gotrain · `config set watchDir` throws away every other watch folder**

Read in code, not reloaded: the panel's Drop folder field (Panel.qml ~834-846) saves on Enter, so pressing Enter on the unchanged field, which shows the first folder, does the same as the last case. Nothing says the second folder is gone, and from then on `sync` and the overdue banner silently stop seeing exports dropped there. When the stored list has more than one entry, replace only its first entry and keep the rest (and never collapse a multi-entry list to the default by popping it); have `config` and `config_view` mention the extra folders (e.g. `~/Downloads (+1 more, edit config.json)`), so the panel shows it too.
   Verify: new test with that config.json: `config set watchDir <dir>` leaves `watchDirs == [<dir>, "~/Sync"]` and `staleDays` untouched; setting it to `~/Downloads` keeps `["~/Downloads","~/Sync"]` rather than `{}`; `config` mentions the second folder; `config --json` (or the panel's view) still gives `watchDir` as the first entry; a config with a single folder or none behaves exactly as today (a set to the default still drops the key).
